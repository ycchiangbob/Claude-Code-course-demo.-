# Kanban Route - Development Guide

This file provides specific guidance for working with the kanban board feature at `/app/kanban/`.

## Feature Overview

A fully-featured drag-and-drop kanban board built with React 19, @dnd-kit, and shadcn/ui components. Supports card and column management with an in-memory state model.

## Architecture

### Component Hierarchy
```
app/kanban/page.tsx (route entry)
  └── KanbanBoard (@/components/kanban/kanban-board.tsx)
      ├── BoardHeader (header with add column button)
      ├── KanbanColumn (@/components/kanban/kanban-column.tsx)
      │   └── KanbanCard (@/components/kanban/kanban-card.tsx)
      ├── CardDialog (create/edit cards)
      └── ColumnDialog (create/edit columns)
```

### File Organization
- **Route**: `app/kanban/page.tsx` - Simple wrapper for KanbanBoard
- **Types**: `lib/types/kanban.ts` - All TypeScript interfaces
- **State**: `hooks/use-kanban-state.ts` - Custom hook managing board state
- **Helpers**: `lib/utils/kanban-helpers.ts` - Pure utility functions
- **Components**: `components/kanban/` - All kanban-specific UI components

## Data Model

### Core Entities

**KanbanCard**
```typescript
{
  id: string;           // UUID generated by crypto.randomUUID()
  title: string;
  description: string;
  tags: string[];       // Array of tag strings
  createdAt: Date;
  updatedAt: Date;
}
```

**KanbanColumn**
```typescript
{
  id: string;           // UUID or predefined ID
  title: string;
  cardIds: string[];    // References to cards in this column
  createdAt: Date;
  updatedAt: Date;
}
```

**KanbanBoard**
```typescript
{
  columns: Record<string, KanbanColumn>;  // Keyed by column.id
  cards: Record<string, KanbanCard>;      // Keyed by card.id
  columnOrder: string[];                  // Determines column display order
}
```

### Default Columns
The initial board includes 5 columns (see `lib/utils/kanban-helpers.ts:getInitialBoard`):
1. Backlog
2. Todo
3. In Progress
4. Review
5. Done

## State Management Rules

### CRITICAL: State is in-memory only
- **NO persistence** - all data is lost on page refresh
- State lives in `useKanbanState` hook using React `useState`
- All updates use immutable patterns
- If persistence is needed, integrate localStorage/backend storage

### State Update Patterns

**Always follow immutable updates**:
```typescript
// CORRECT
setBoard((prev) => ({
  ...prev,
  cards: {
    ...prev.cards,
    [cardId]: updatedCard,
  },
}));

// INCORRECT - mutates state
board.cards[cardId] = updatedCard;
setBoard(board);
```

**Update timestamps** when modifying entities:
```typescript
updatedAt: new Date()
```

**Maintain referential integrity**:
- When deleting a column, delete all its cards
- When deleting a card, remove its ID from parent column's `cardIds`
- Keep `columnOrder` in sync with `columns` keys

## Drag-and-Drop Implementation

### Library: @dnd-kit

**Key Concepts**:
- Uses `DndContext` for drag-and-drop scope
- `SortableContext` for reorderable lists
- `useSortable` hook for draggable items
- `useDroppable` hook for drop zones

### Two Drag Modes

1. **Column Reordering** (`kanban-board.tsx:59-65`)
   - Horizontal sorting of columns
   - Updates `board.columnOrder` array
   - Uses `horizontalListSortingStrategy`

2. **Card Movement** (`kanban-board.tsx:66-93`)
   - Move cards within/between columns
   - Updates source/destination column `cardIds`
   - Uses `verticalListSortingStrategy` for cards

### Drag Types
Each draggable element has a `type` in its data:
```typescript
// Column
{ type: 'column' }

// Card
{ type: 'card' }
```

**IMPORTANT**: Always check `active.data.current?.type` and `over.data.current?.type` in drag handlers.

### Activation Constraint
Requires 8px movement before drag starts (prevents accidental drags):
```typescript
activationConstraint: { distance: 8 }
```

## UI/UX Guidelines

### Visual Design

**Color System**:
- Columns use auto-generated colors based on title hash
- 5 color schemes: blue, purple, green, orange, pink
- Colors applied to: border-top, background, badge

**Dark Mode**:
- All components support dark mode via `dark:` Tailwind classes
- Use semantic colors (gray-900/gray-100) for text
- Background gradients: light (slate/blue/indigo) vs dark variants

**Animations**:
- Use `transition-all duration-200` for hover effects
- Drag elements have opacity/scale changes
- Smooth shadow transitions on hover

### Component Patterns

**Empty States**:
- Show helpful empty states when no columns/cards exist
- Include icons (lucide-react) and descriptive text
- Suggest next action (e.g., "Get started by creating your first column")

**Dialogs**:
- Use shadcn/ui Dialog components
- Support both create and edit modes
- Pass `initialCard`/`initialColumn` for editing
- Clear state on close

**Confirmations**:
- Use native `confirm()` for destructive actions
- Show context (e.g., "This will delete X cards") when relevant
- See `kanban-board.tsx:119` and `kanban-board.tsx:144`

## Development Rules

### When Adding Features

1. **Check state management first**
   - Does `useKanbanState` need new actions?
   - Will you need new helper functions?

2. **Update types**
   - Add new fields to interfaces in `lib/types/kanban.ts`
   - Export form types using `Omit<>` pattern

3. **Maintain immutability**
   - Always spread previous state
   - Never mutate arrays/objects directly

4. **Handle timestamps**
   - Set `createdAt` and `updatedAt` for new entities
   - Update `updatedAt` on modifications

5. **Preserve referential integrity**
   - Keep `cardIds`, `columns`, `cards`, and `columnOrder` in sync
   - Test delete operations thoroughly

### When Modifying Drag-and-Drop

**Before changing drag logic**:
- Understand both drag modes (cards vs columns)
- Test cross-column and same-column movements
- Verify edge cases (empty columns, single card, etc.)

**Common gotchas**:
- Don't mix up `activeId`/`overId` with `sourceColumnId`/`destColumnId`
- Remember cards can be dropped on columns OR other cards
- Handle case when `over` is null (dragged outside drop zones)

### Component Guidelines

**Creating new components**:
- Place kanban-specific components in `components/kanban/`
- Import types from `@/lib/types/kanban`
- Use shadcn/ui components for consistency
- Follow existing naming: `kanban-*.tsx`

**Styling**:
- Use Tailwind utility classes
- Maintain existing color palette
- Support dark mode for all new components
- Match existing spacing/sizing patterns

## Common Tasks

### Adding a new field to cards

1. Update `KanbanCard` interface in `lib/types/kanban.ts`
2. Update `createCard` in `lib/utils/kanban-helpers.ts`
3. Add form field in `components/kanban/card-dialog.tsx`
4. Display field in `components/kanban/kanban-card.tsx`
5. Update `getInitialBoard()` if needed for sample data

### Adding persistence (localStorage/backend)

1. Create a persistence layer (e.g., `lib/storage/kanban-storage.ts`)
2. Modify `useKanbanState` to load initial state from storage
3. Add `useEffect` to save state changes
4. Consider debouncing saves for performance
5. Add error handling for storage failures

### Adding new column management features

1. Add action to `useKanbanState` hook
2. Update UI in `components/kanban/kanban-column.tsx`
3. Wire up in `components/kanban/kanban-board.tsx`
4. Test column reordering still works

## Performance Considerations

- State updates are immutable but create new objects - this is intentional
- Card rendering is optimized via React keys (use `card.id`)
- Large boards (100+ cards) may need virtualization
- Consider `React.memo()` for `KanbanCard` if performance degrades

## Gotchas and Known Issues

1. **No persistence** - remind users data is temporary
2. **Native confirm()** - not styled, consider custom modal for better UX
3. **Column colors** - hash-based, same title = same color
4. **Drag activation** - 8px threshold can feel sluggish on high-DPI displays
5. **Timestamps** - stored as Date objects, may need serialization for persistence
